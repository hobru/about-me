## Website layout

**Editorial personal homepage + searchable professional library**, rather than a chronological social feed:

1. **Identity and focus:** short positioning statement, SAP/Microsoft integration, AI/agents, data/security, and direct podcast/GitHub links.
2. **Selected work:** a small editorial selection of a recent talk, milestone episode, guest appearance, and historical session. `featured` flags control this; there is no invented popularity ranking.
3. **Full catalogue:** keyword search, multi-select format checkboxes, year/evidence filters, newest-first ordering, incremental rendering, source links, exact roles, and expandable evidence/date notes. Select any combination of formats, choose **Without podcasts** to omit the series episode records, or **All formats** to restore them. Deselecting every format shows no matches; **Reset** clears all filters. Listen / Read / Build select just their corresponding format.
4. **About and professional profiles:** concise introduction and links to public professional profiles.
5. **Internal companion:** a separate authenticated SharePoint/M365 destination, not a hidden public website tab. No internal metadata is shipped with this site.

The website uses warm neutral surfaces, a rose accent, local system fonts, light/dark mode, keyboard-accessible controls, and a mobile layout. It deliberately avoids third-party embeds, tracking, copied articles, media downloads, and externally loaded images/fonts.

Source and external links open in a new tab/window with opener and referrer protection. In-page navigation stays in the current page, and the catalogue download remains a download.

The landing page borrows hierarchy, a prominent primary action, nearby evidence, and more deliberate spacing from [elayadesign's landing-page design guide](https://github.com/elayadesign/ai-design-skills/blob/main/skills/landing-page-design/SKILL.md), as inspiration rather than a specification. It remains a personal editorial homepage, not a sales funnel: a real SIT Weinheim recording anchors the hero, catalogue counts retain their qualifications, and Listen / Read / Build shortcuts filter the existing library. There are no invented endorsements or testimonials, unnecessary signup forms, or mandatory scroll effects. The existing theme and system fonts are preserved; entrance and hover movement respect reduced-motion preferences.

## Files and maintenance

| Path | Purpose |
| --- | --- |
| `data/public.json` | Hand-curated research metadata, including unresolved public-source leads and attribution caveats |
| `data/podcast.json` | Reproducible snapshot of the public podcast index |
| `tools/import_podcast.py` | Optional network refresh of episode metadata only |
| `tools/import_sap_community.py` | Offline import of supplied SAP Community search Markdown; explicit bylines, reviewed relationship IDs, and uncertain historical leads only |
| `tools/build.py` | Offline build from two explicit inputs; excludes Needs review records from all public outputs |
| `site/` | Entire deployable site, including generated JS/JSON catalogue |
| `tools/test_catalogue.py` | Focused importer, schema, and public-boundary checks |

Each record carries a source URL, attribution URL, role, topics, evidence level, check date, and optional publication/event date. Date precision is preserved as year, month, day, or unknown. Event delivery is not inferred from an agenda, invitation, or file modification date.

Evidence labels:

- **Source reviewed:** relevant public page was read; this is not a guarantee of every linked asset's contents.
- **Search indexed:** evidence comes from an indexed excerpt, not a full-page review.
- **User-provided excerpt:** evidence comes from search-result metadata pasted by the user, not an independently reviewed original page.
- **User-provided reference:** metadata or attribution comes from a supplied reference inventory, not an independently reviewed original. Relevant limitations remain in the source notes.
- **Series index:** episode metadata imported from the public series index; per-episode participation and every media URL have not been independently checked.
- **Needs review:** unresolved role, attribution, or identity question; retained for research only and excluded from publication.

The publication build removes operational retrieval diagnostics from SAP search-listing notes while retaining their actual evidence limitations. It does not upgrade evidence labels, assume event delivery, or remove role/date caveats. Research notes remain unchanged in the input files.

Only metadata, concise original notes, and outbound links are stored. No third-party articles, slides, recordings, or transcripts are republished.

### Build and preview (PowerShell, Python 3.10+)

No package installation or server-side application is required.

```powershell
# Optional: refresh the public podcast index. Requires internet access.
python tools\import_podcast.py

# Optional: import a user-supplied search excerpt kept outside public inputs.
# Do not commit raw signed-in page copies. Review the resulting metadata.
python tools\import_sap_community.py --input .local\sap-community-search.md

# Offline build and checks
python tools\build.py
python -m unittest discover -s tools -p "test_*.py"
node --check site\app.js

# Optional: generate a portable single-file preview (not deployed automatically)
python tools\build.py --standalone .local\website-proposal.html

# Local preview; binds only to this computer
python -m http.server 8037 --bind 127.0.0.1 --directory site
```

Open `http://127.0.0.1:8037`. The generated site also works by opening `site\index.html` directly; data is loaded from a local JS asset, not a cross-origin `fetch`. Node is only needed for the optional JavaScript syntax check.

The importer rejects missing titles/dates, duplicate episode numbers, empty results, and a decrease in the existing snapshot count. Refreshes update series metadata while preserving item-level role/evidence/check dates, including unresolved participation questions, instead of replacing them with series-wide assumptions. Episode 16 has a malformed video link in the source index: its episode page is retained with an explicit caveat and no fabricated YouTube link. Review that at the source. Automated refresh is intentionally not enabled.

The SAP Community importer removes search tracking parameters and deduplicates repeated excerpts and existing content IDs, including migrated `m-p` / `ba-p` and event `ec-p` / `ev-p` aliases. The build independently rejects duplicate SAP content IDs. Search imports do not replace reviewed or separately supplied reference evidence with weaker snippets. Announcement publication dates do not overwrite existing advertised event dates. Truncated titles are not silently reconstructed; complete titles supplied separately are identified in the source notes.

The build reads only the two named public datasets and rejects known Microsoft internal source hosts in record URLs. This is a guardrail, **not a general data-loss-prevention classifier**: manually review new public records and every deployment artifact.

## Hosting and deployment

**Primary site: [https://hobru.github.io/about-me/](https://hobru.github.io/about-me/).** GitHub Pages serves the HTTPS site. `http://holger.bruchelt.de/` is intended as an independent copy on the existing hosting account, not a GitHub Pages custom domain.

The repository is public, including its research inputs and history. **Needs review** excludes a record from the website; it is not access control for research data. The internal companion remains outside both Git and all deployment artifacts.

### GitHub Pages

The [Publish website workflow](.github/workflows/pages.yml) runs on pushes to `main` and can also be started manually:

1. Check out the source and build the public catalogue offline.
2. Run the Python checks and JavaScript syntax check.
3. Upload **only `site`** as the Pages artifact and as the downloadable **static-site** artifact.
4. Deploy through the `github-pages` environment with Pages write and OIDC permissions restricted to the deployment job. Actions are pinned to verified release commit SHAs.

GitHub Pages has HTTPS enforcement enabled. Keep its custom-domain setting empty and do not add `site/CNAME`: binding `holger.bruchelt.de` would redirect the GitHub address away from the requested primary site.

### Independent copy at holger.bruchelt.de

Download **static-site** from a successful workflow run, or build locally and use the contents of `site`. Extract/upload those files directly into the document root assigned to `holger.bruchelt.de` through the hosting provider's authorized file manager, FTPS, or SFTP. Do not upload the repository root, raw research inputs, or session artifacts.

The same files work over HTTP and HTTPS and at either a project path or domain root: all application assets are relative, and no server runtime or secure-context API is required. The canonical link identifies the HTTPS GitHub page as primary without redirecting visitors away from the mirror.

Keep the existing subdomain DNS and the parent domain's website/email settings unchanged. The GitHub workflow does not upload to the separate hosting account; the copy must be refreshed there after updates. Hosting access and successful retrieval of the mirror have not been verified.

Before a real public launch, review applicable German imprint/privacy requirements, accessibility, branding, and publication permissions. No legal notice or personal address has been invented.
